## Build it yourself
```bash
docker build -t my-comfy-workflow .
docker run --rm --gpus all -p 8188:8188 -p 8000:8000 \
  -e SERVE_API_LOCALLY=true -e COMFY_ORG_API_KEY=$COMFY_ORG_API_KEY \
  my-comfy-workflow
```
This workflow generates video through the Comfy.org LTXV API rather than a local
checkpoint, so no model weights are baked into the image and no HuggingFace or
CivitAI tokens are needed at build time.

## Required: Comfy.org API key

`LtxvApiImageToVideo` is an API node — it runs on Comfy.org's servers, not on the
endpoint's GPU, and bills against your Comfy.org account. Set `COMFY_ORG_API_KEY`
as an environment variable on the endpoint (or pass `input.comfy_org_api_key` per
request). Without it the handler fails immediately with an explanatory error
instead of a cryptic node failure.

## Deploy on Runpod Serverless
1. Connect this repository at https://runpod.io/console/serverless
2. Create a new endpoint, select **Deploy from GitHub**
3. Pick this repo, branch `main`
4. Runpod's builder will build the Dockerfile and host the resulting image
5. Hit the endpoint with `/run` or `/runsync`

Example request:

```json
{
  "input": {
    "prompt": "Camera slowly pushes in, the subject blinks and turns toward the window.",
    "image": "BASE64_ENCODED_PNG_OR_JPEG",
    "duration": 8,
    "resolution": "1920x1080",
    "fps": 25,
    "generate_audio": true
  }
}
```

`image` may be raw base64 or a data URL like `data:image/png;base64,...`.

The worker loads the image-to-video `api-workflow.json` by default. You can override any node inputs:

```json
{
  "input": {
    "node_inputs": {
      "3": {
        "duration": 8,
        "resolution": "1920x1080",
        "fps": 25,
        "generate_audio": true
      }
    }
  }
}
```

`duration` and `fps` are numbers, not strings — `LtxvApiImageToVideo` validates
them against fixed lists and rejects `"8"` where it expects `8`. Accepted values:

| field | accepted values |
| --- | --- |
| `model` | `LTX-2 (Pro)`, `LTX-2 (Fast)` |
| `duration` | `6`, `8`, `10`, `12`, `14`, `16`, `18`, `20` (over `10` needs `LTX-2 (Fast)` at `1920x1080` / `25` fps) |
| `resolution` | `1920x1080`, `2560x1440`, `3840x2160` |
| `fps` | `25`, `50` |

You can also submit a full ComfyUI API workflow as `input.workflow`.

LoRAs are applied only when the request includes a LoRA field. Use `lora_name` or `lora` for one LoRA, or `loras` for multiple. The submitted workflow must contain `LoraLoader` nodes:

```json
{
  "input": {
    "prompt": "Camera slowly pushes in.",
    "image": "BASE64_ENCODED_PNG_OR_JPEG",
    "lora_name": "my-style-lora.safetensors"
  }
}
```

For multiple LoRAs:

```json
{
  "input": {
    "prompt": "Camera slowly pushes in.",
    "image": "BASE64_ENCODED_PNG_OR_JPEG",
    "loras": [
      {
        "name": "my-style-lora.safetensors",
        "strength": 0.8
      }
    ]
  }
}
```

The default built-in LTXV API workflow does not have LoRA loader nodes, so send a custom `input.workflow` if you need LoRAs.

## Files
- `Dockerfile` — generated by comfyui-wizard, fully resolved
- `handler.py` — Runpod Serverless handler; the base image's `/start.sh` launches
  ComfyUI and then runs this, which submits the API workflow and returns the outputs
- `workflow.json` — the raw workflow, as you designed it in ComfyUI
  (LTX 2.5 **text**-to-video; kept for reference, not used at runtime)
- `api-workflow.json` — ComfyUI's `/prompt` API shape, and what the worker runs.
  It is an **image**-to-video graph, so it deliberately differs from
  `workflow.json`; edit this file to change endpoint behaviour.
- `README.md` — this file
